# Map Signal — an FTL mod

Writes one line to `FTL_HS.log` each time you open or close the star map:

```
map-signal: loaded
map-signal: open sector 3
map-signal: closed sector 3
```

That is the whole mod. Nothing is drawn, no event, choice, reward, ship or probability
changes, and no save byte is written.

## What it is for

The [save watcher](../../tools/SAVE-WATCH.md) shows the card for the event you are looking at,
on a second monitor. It would rather show the **sector profile** while you are on the map
planning a route — but the save file cannot tell it that. FTL writes the save during
encounters and is silent while the map is up, so the watcher had to approximate: it showed the
profile at the entry beacon, when no card resolved, and for a while after arriving somewhere
new.

Hyperspace exposes `starMap.bOpen` — the flag the game itself uses. Lua cannot write files
(`io`, `os` and `package` are cut from its sandbox) but it *can* `log()`, and the log is a file
a program outside the game can read. So the mod turns a screen the watcher cannot see into a
line it can.

With this installed the watcher stops guessing: open map → sector profile, closed map → card.

## Requires Hyperspace

The star map is drawn by compiled code in `FTLGame.exe`, and `bOpen` lives there. Slipstream
patches data; only Hyperspace reaches the runtime.

## Install

From the repo root, with **FTL closed**:

```
python tools\build-map-signal-mod.py --install
```

Then relaunch through `mods\fullscreen-no-minimize\launch-ftl.cmd`, never `FTLGame.exe`
directly, or the two-monitor fix is lost (CLAUDE.md §5.2d).

`--install` reverts to vanilla and re-applies `Hyperspace.ftl`, `event-labels.ftl` and this
mod, in that order. That list is `PATCH_ORDER` in the builder and is the authoritative record
of what a full install applies — Slipstream's `--patch` applies *exactly* what it is given, so
a mod missing from the list is a mod uninstalled.

## Uninstall

From `C:\Users\jparr\Documents\Slipstream`, the same patch minus this mod:

```
java -jar modman.jar --patch Hyperspace.ftl event-labels.ftl
```

Safe mid-run either way: the mod is log-only and touches no save byte. Do **not** run `--patch`
with no mods at all — it throws a NullPointerException. To reach true vanilla, copy
`Slipstream\backup\ftl.dat.bak` over the game's `ftl.dat`.

## Did it work?

`FTL_HS.log` answers without a screenshot:

- `map-signal: loaded` after launch — the script registered.
- `map-signal: open sector N` the first time you open the map — the flag is being read.

An error inside the per-frame hook is caught and logged **once per site**, never per frame, so
a fault cannot spam the log or take the game down.

## Notes

- The script is generated by `tools/build-map-signal-mod.py`; edit that, not
  `src/data/map-signal.lua`.
- The build checks the lines it emits against the watcher's own regex, so the two halves of
  this contract cannot drift apart silently.
- The sector number in the line is a sanity check for a human reading the log. The watcher
  takes the sector from the engine's own `Sector: CIVILIAN_SECTOR` generation lines, which name
  the type rather than the number.
- Hyperspace stamps `[Lua]: ` on every scripted line, so the file actually reads
  `[Lua]: map-signal: open sector 2`. The watcher's pattern allows the tag.
- **The installed build prints a rougher sector number** than the source does: `sector 2.0`
  in a run, and uninitialised memory (`sector 1835609917.0`) at the main menu, where no run is
  loaded. Fixed in the builder — integer-formatted, and anything outside sectors 1–8 reported
  as `?` — and packed, but not yet patched in, because it is cosmetic and reinstalling means
  closing the game. It reaches the game at the next `--install`. The watcher never reads the
  suffix.
